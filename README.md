## Problem Statement

Fintech businesses process large volumes of payments, refunds, fees, and settlements across multiple systems. Manually checking these records is time-consuming and often results in missed discrepancies.

Regional pricing adds further complexity, since billing country, card country, and IP-based location don't always align.

This project automates the reconciliation process and uses AI to investigate exceptions that require further analysis.

## Objectives

- Automatically reconcile financial transactions
- Detect payment and pricing mismatches
- Detect settlement discrepancies
- Identify refund and adjustment differences
- Use billing country, card country, and IP country as regional signals
- Retrieve the pricing policy relevant to a transaction
- Use an LLM to investigate exceptions
- Generate explanations, confidence scores, and recommendations
- Calculate the financial impact of discrepancies
- Store investigation results for audit and review

## System Workflow

```
Transaction Data
      ↓
Deterministic Reconciliation
      ↓
Exception Detection
      ↓
Relevant Policy Retrieval
      ↓
Financial Evidence Collection
      ↓
Groq LLM Investigation
      ↓
Classification + Explanation
      ↓
Recommendation + Audit Result
```

## Reconciliation Engine

The reconciliation engine performs deterministic checks **before** any AI investigation runs. Checks include:

| Category | Check |
|---|---|
| Pricing | Payment amount vs. expected price |
| Pricing | Pricing policy differences |
| Payments | Payment status |
| Fees | Fee validation |
| Refunds | Refund and adjustment differences |
| Settlements | Expected vs. actual settlement |
| Settlements | Settlement differences |
| Location | Billing country vs. card country |
| Location | Billing country vs. IP country |

Core financial calculations are handled entirely by deterministic rules — not the LLM.

## AI Investigation

Exceptions flagged by the reconciliation engine are investigated using **Groq**.

**Input provided to the AI:**
- Transaction data
- Reconciliation result
- Relevant pricing policy

**Output generated by the AI:**
- Exception classification
- Explanation
- Confidence score
- Financial impact
- Supporting evidence
- Recommendation

> The LLM is used purely for investigation and explanation — it never replaces the deterministic financial calculations.

## Policy Retrieval

The system maintains regional pricing policies for different plans and countries.

**Example — Starter Plan:**

| Country | Price |
|---|---|
| India | ₹1,000 |
| Singapore | ₹1,800 |
| Germany | ₹2,200 |
| United Kingdom | ₹2,100 |
| United States | ₹2,500 |

The relevant policy is retrieved based on the transaction's plan and billing country, and passed to the AI as investigation evidence.

## Examples

### Example 1 — Pricing Mismatch

**Transaction:** `TXN0001`

| Field | Value |
|---|---|
| Plan | Starter |
| Billing Country | GB |
| Expected Price | ₹2,100 |
| Payment Received | ₹1,470 |
| Difference | ₹630 |

The reconciliation engine flags the pricing mismatch. The AI investigates using the pricing policy and transaction evidence, identifies the ₹630 shortfall, and recommends checking for an approved discount, promotional code, or manual adjustment before taking corrective action.

### Example 2 — Settlement Mismatch

**Transaction:** `TXN0011`

| Field | Value |
|---|---|
| Expected Settlement | ₹15,680 |
| Actual Settlement | ₹15,380 |
| Difference | ₹300 |
| Adjustment Amount | ₹300 |

The AI identifies that the ₹300 adjustment exactly explains the settlement difference. Rather than flagging this as fraud, it recommends confirming that the adjustment was authorized and correctly applied.

## Getting Started

### Backend

1. Create a virtual environment:
   ```bash
   python -m venv venv
   ```

2. Activate it:
   ```bash
   # Windows
   .\venv\Scripts\activate
   ```

3. Install dependencies:
   ```bash
   pip install fastapi uvicorn openai python-dotenv
   ```

4. Create a `.env` file:
   ```
   GROQ_API_KEY=your_api_key
   ```

5. Start the backend:
   ```bash
   uvicorn src.main:app --reload
   ```

   Backend runs at: `http://127.0.0.1:8000`

### Frontend

1. Open another terminal:
   ```bash
   cd frontend
   ```

2. Install dependencies:
   ```bash
   npm install
   ```

3. Start the frontend:
   ```bash
   npm run dev
   ```

   Frontend runs at: `http://localhost:5173`

## Design Decisions

- Financial calculations are deterministic.
- The LLM is used strictly for investigation and explanation.
- Policy information is retrieved and provided as evidence to the AI.
- Regional differences are treated as review signals, not automatically classified as fraud.
- AI-generated financial impact is grounded in deterministic reconciliation results.
- Investigation results are persisted for audit and review.

## Limitations

- The current dataset is synthetic.
- This is a prototype and is not connected to real payment or settlement systems.
- AI investigation currently runs on individual exceptions, not batches.
- Production use would require authentication, database persistence, and additional monitoring.
- More extensive LLM evaluation would be required before production deployment.
